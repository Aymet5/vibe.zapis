# ВАЙБ — сайт записи и накопительных скидок

Онлайн-запись в парикмахерскую «ВАЙБ» (г. Кызыл) с накопительной скидкой,
входом через ВКонтакте, ботом для подтверждений и напоминаний и панелью
администратора.

## Что умеет

- **Свободные окошки.** Витрина расписания всех мастеров на выбранный день.
  Сетка с шагом 30 минут (обычная стрижка), длинные услуги закрывают
  несколько окошек подряд. Занять одно окошко дважды нельзя — проверка идёт
  в транзакции при создании записи.
- **Вход через ВКонтакте** (VK ID, OAuth 2.1 + PKCE). Отдельная регистрация
  не нужна: первый вход заводит карточку клиента. Записаться без входа нельзя —
  у каждой записи есть подтверждённый профиль, копится скидка и бот может
  написать клиенту.
- **Накопительная скидка.** 5% за каждый состоявшийся визит, максимум 20%.
  Копить можно долго, потратить — на одну стрижку, целиком или частями.
- **Списание через панель.** При записи клиент заявляет, сколько процентов
  хочет потратить, — они резервируются, чтобы их нельзя было использовать
  дважды. Окончательно списывает администратор при завершении визита;
  неиспользованный остаток возвращается на счёт, отмена возвращает всё.
- **Бот ВКонтакте.** Подтверждение записи с кнопками «Всё верно» / «Отменить»,
  напоминание за несколько часов до визита, сообщение о новом балансе после
  стрижки. Отвечает на вопрос о скидке в личных сообщениях.
- **Панель администратора** на `/admin`: записи по дням, подтверждение,
  завершение визита со списанием, неявка, отмена, поиск клиентов и ручная
  корректировка процентов. На вкладке «Мастера» — загрузка фотографии и
  привязка мастера к его аккаунту ВКонтакте.
- **Кабинет мастера.** Мастер входит на сайт через ВК своим аккаунтом и видит
  в личном кабинете только свои записи с телефонами клиентов. Доступ даёт
  администратор, вписав id ВКонтакте в карточку мастера.
- **Уведомления администраторам** о новых записях и отменах — в Telegram и в
  рабочую беседу мастеров ВКонтакте (`VK_ADMIN_PEER_IDS`).

## Требования

- Node.js 20 или новее
- Домен с HTTPS (ВКонтакте не отдаёт данные на http)

## Запуск на своём сервере

```bash
git clone <репозиторий> /opt/vibe && cd /opt/vibe
npm ci
cp .env.example .env && nano .env   # заполнить ключи, см. комментарии в файле
npm run build                       # собрать фронтенд в dist/
npm start                           # запустить сервер
```

Сервер отдаёт и API, и собранный фронтенд на одном порту (`PORT`, по
умолчанию 3001). После каждого обновления кода нужно повторить
`npm run build` и перезапустить сервис.

Установка зависимостей от root требует `npm ci --unsafe-perm`: иначе npm
понижает права при сборке нативного модуля `better-sqlite3` и она падает.

### pm2 (так развёрнут рабочий сервер)

```bash
pm2 start npm --name vibe --cwd /opt/vibe -- start
pm2 save                      # чтобы процесс поднялся после перезагрузки
pm2 startup                   # один раз, если pm2 ещё не в автозапуске
```

Обновление после изменений в коде:

```bash
cd /opt/vibe && git pull && npm ci --unsafe-perm && npm run build && pm2 restart vibe
```

Логи — `pm2 logs vibe`.

### systemd (альтернатива pm2)

`/etc/systemd/system/vibe.service`:

```ini
[Unit]
Description=VIBE booking
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/vibe
ExecStart=/usr/bin/npm start
Restart=always
User=www-data
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now vibe
```

### nginx

Домен сайта — **vibe-cut.ru** (A-запись должна указывать на IP сервера).

```nginx
server {
    server_name vibe-cut.ru www.vibe-cut.ru;
    listen 443 ssl;
    # ssl_certificate ... (например, от certbot)
    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Заголовок `X-Forwarded-For` важен: по нему считается лимит попыток ввода
пароля в панель.

Сертификат выпускается certbot'ом, он же дописывает секцию `ssl_*` и редирект
с 80 порта:

```bash
certbot --nginx -d vibe-cut.ru -d www.vibe-cut.ru
```

```bash

```

## Данные

Всё хранится в SQLite по пути `DATABASE_PATH` (по умолчанию `data/vibe.sqlite`).
В этом файле накопленные скидки клиентов — **делайте резервные копии**:

```bash
sqlite3 data/vibe.sqlite ".backup '/var/backups/vibe-$(date +%F).sqlite'"
```

Фотографии мастеров лежат рядом, в `data/uploads` (`UPLOADS_PATH`), и отдаются
по `/uploads/…`. В `dist` они не попадают, поэтому пересборка их не трогает,
но в резервную копию каталог включить нужно.

Таблицы: `users` (клиенты и баланс), `bookings` (записи),
`bonus_transactions` (журнал движения процентов — каждое начисление,
резерв, возврат и списание), `sessions`, `oauth_states`.

## Услуги, мастера и режим работы

Прайс, длительность услуг, состав мастеров, часы работы и шаг сетки окошек
лежат в одном файле — [`shared/catalog.ts`](shared/catalog.ts). Его используют
и сайт, и сервер, так что менять цены и услуги нужно только там (после
изменения — `npm run build` и перезапуск).

## Безопасность

- Токены и пароли читаются только из `.env` на сервере, в браузер не попадают.
- Панель администратора закрыта паролем `ADMIN_PASSWORD`, сессия живёт 12 часов,
  подбор пароля ограничен 10 попытками за 15 минут с одного адреса.
- Callback API ВКонтакте принимает события только с совпадающим
  `VK_CALLBACK_SECRET`.

## Про Vercel

В репозитории остался `vercel.json` от прежней версии сайта. На Vercel
работает только статика: там нет постоянного диска под SQLite и нет фонового
процесса для напоминаний, поэтому вход, скидки и бот на нём работать не будут.
Рабочий вариант — собственный сервер, как описано выше.
